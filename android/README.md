# 迁匣 1.0.0

Android 9 及以上的独立备份迁移 App。此版本实现普通模式：应用安装包（包括 split APK）和用户主动选择的文件，密码加密、本地导出、WebDAV 上传下载、解密校验、系统确认安装，以及每日后台备份。

## 手机上的使用步骤

1. 安装 `Qianxia-1.0.0.apk`。
2. 旧手机：选应用。要迁移应用数据，先在该应用里主动导出，再在迁匣点“添加应用导出的数据 / 其他文件”。
3. 在“网盘”页填写网盘提供的 WebDAV 目录地址、账号和应用密码，测试成功后保存。请使用已经存在的目录；新旧手机填同一个目录。建议 HTTPS。
4. 开始备份，设置至少 8 位的恢复密码；可勾选备份后上传。上传成功前，本地记录不会显示云端完成。
5. 新手机：安装迁匣，连接同一网盘，读取备份列表并下载。在“恢复”页输入原密码解密。
6. 完整性校验通过后，分别确认安装应用、保存数据文件，再在对应应用里导入。安装包与数据导入分开记录。

如果网盘没有 WebDAV：旧手机在备份记录中选“分享给网盘 App”；新手机在网盘 App 中下载 `.qxb`，再到迁匣中导入。不需要旧手机在线。

## 已实现

- 用户应用列表、搜索、多选；选择持久保存。
- 基础 APK 与所有安装拆分 APK 集合备份。
- 系统文件选择器授权文件；数据、照片等可作为文件加入备份。
- PBKDF2-HMAC-SHA256（210000 次）+ AES-256-GCM 分块加密；终止记录检测不完整文件。
- 备份清单与每个文件的 SHA-256 校验；安全展开阻止目录穿越。
- WebDAV 读写测试、上传、下载、Unicode 文件名与云端列表。
- 上传到 `.uploading`，完整读回并校验后通过 MOVE 发布 `.qxb`；服务器必须支持 PROPFIND、PUT、GET、MOVE、DELETE。测试连接会创建并删除一个独立测试文件。
- 本地保留加密备份，网盘失败时可重新上传。v1 重新上传完整文件，不支持字节级断点续传。
- 前台服务执行手动任务，避免所有操作挤在主线程。
- Android JobScheduler 每 24 小时执行自动备份，条件为不计费网络与充电；系统可能延后执行。失败上传先重试已有备份，避免每次重试都生成新的副本。
- WebDAV 密码及自动备份密码通过本机 Android Keystore 加密保存。开启自动备份时需明确设置密码。
- 解密后经 PackageInstaller 安装完整 APK 集合，用户完成系统确认；没有静默安装。
- 原数据文件保存到用户选择的位置，由原应用导入。

## 当前边界

- **尚未实现 Root 私有应用数据备份恢复。** 普通模式无法读取其他 App 的内部数据库、私有聊天记录或登录凭证。安装包不能替代数据备份。
- 不是小米系统换机的系统权限级替代品。系统应用、工作资料、多用户、短信与系统设置未提供专门迁移。
- OneDrive、Google Drive、百度网盘、阿里云盘官方 API 未直接接入；可使用它们提供的 WebDAV 或手动上传/下载流程。
- 自动备份不能替其他 App 自动导出私有数据，只能备份当前可读的安装包与已授权文件。
- 某些拆分安装包依赖设备架构、Android 版本；签名不匹配或版本不兼容会由系统拒绝安装，结果显示失败。需要时可从原应用来源重新安装，再导入数据。
- 恢复密码不上传、不提供找回；忘记密码将无法解密。关闭自动备份会移除本机保存的自动备份密码，但不改变已有备份的密码。
- 目前不会自动删除云端旧版本，可自行管理网盘空间。
- Android 厂商的后台限制可能延后或中断自动任务；手动任务中断后请从本地记录重试。

## 构建与验证

`build.sh` 使用 Android SDK 35、Build Tools 35.0.0、Java 17。无 javac 时使用随包提供的 Eclipse ECJ 编译器。

```bash
QIANXIA_SDK=/absolute/path/to/android-sdk bash build.sh
bash test-core.sh
```

构建输出在 `build/Qianxia-1.0.0.apk`。源码不包含发布签名私钥。若本机没有 `signing/development.jks`，脚本生成开发签名；自行构建版本的签名与交付版本可能不同，覆盖安装需要保持同一签名。

验证结果见 `verification/TEST-REPORT.md`。模拟器验证不代表所有手机、网盘服务和应用的兼容性已覆盖。
